# Shared contracts

`prd.schema.json` is the supplied PRD contract, copied unchanged. It defines
Evidence, SourceRange, Entity, Relation, Coverage, Graph, Finding, Answer,
ChangePack, AnalysisRun and ApiError. These are data contracts, not a claim that
the deferred analysis engines exist.

`structure-1.1.schema.json` is generated by `python3 scripts/build_contracts.py`.
It preserves the original definitions and makes only the following versioned
changes for this slice:

- Graph and AnalysisRun carry `schema_version: "1.1"`.
- Entity adds `repository` and `virtual_group` kinds, optional file/parent IDs,
  direct child counts, and metadata. A virtual group's path may be null. Real
  directories use the PRD's `folder` kind.
- Relation adds `groups` (explicit view-only membership) and an `unresolved`
  flag. Containment and group membership have empty source-line evidence; they
  are inventory/view facts, not claims of semantic analysis.
- Coverage adds total/returned entity counts. Graph adds focus path and sibling
  pagination fields. A diagram page contains its focus node plus ≤3 children;
  the graph endpoint is independently bounded to ≤12 entities.
- AnalysisRun adds project/result IDs, timestamps and optional progress, and
  replaces string diagnostics with file/stage/message/severity records. No
  fake percentage is emitted for an unknown denominator.

The project, snapshot, file inventory, source slice, capability and preference
models live in `backend/app/models/v1`. Their new API definitions are published
in FastAPI's `/openapi.json`. They supplement the PRD schema, which does not
specify these payloads in JSON Schema. Empty source files have total_lines=0,
line_start=1, line_end=0 and empty content; nonempty ranges are 1-based inclusive.

TypeScript evidence and future result types are generated directly from these
schemas into `frontend/src/types/v1/{prd,structure}.generated.ts` by
`cd frontend && npm run contracts`. Never redefine evidence, findings or answers
inside an individual feature. `FeatureContracts.ts` adds only summary,
document, finding-page and dependency-overlay envelopes not supplied by the PRD;
they are explicitly 1.1. The runtime registry passes canonical workspace identity
and abort signals and never synthesizes results.

Live graph/run responses are checked with JSON Schema in
`backend/tests/test_v1_boundaries.py`. The isolated extension mounting example
is in `frontend/src/contexts/SlotRegistry.test.tsx`; it is test-only.

IDs: project/snapshot/run IDs are random 32-character hex. A file/folder/root ID
is the first 32 hex characters of SHA-256 of
`1.0:{snapshot_id}:{kind}:{normalized_path}`. Files use `file`, directories use
`folder`, and root uses `repository` with path `.`. Snapshot-scoped IDs prevent
accidental cross-snapshot joins. The Archify compiler prefixes node IDs with
`n_` solely to meet upstream syntax; an explicit manifest mapping translates
back to the canonical ID at the audited bridge.
